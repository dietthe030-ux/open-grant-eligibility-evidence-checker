# Stage 2 — Implementation Specification

`TreeMap[str, Application]`: owner, grant_url, region, org_type, submitted_at:u64, state, outcome, matched_criteria, failed_criteria, evidence_digest, retry_count:u8. API: `create_application`, `freeze_application`, `assess_application`, `retry_unresolved`, views. Caller cannot supply `eligible`; validate source identity and bounded facts. Leader/validator independently extract criterion IDs and compare normalized outcome and criterion sets. WRONG: `assess(case_id, eligible: bool)`. CORRECT: `assess(case_id)` derives result only from frozen inputs and source. Test opposite callers, deadline boundaries, missing criteria, source outage, disagreement and serialized return. Frontend must display disclaimer and actual transaction lifecycle.

Revision 2 schema adds `declared_facts_notice`, canonical `region_criterion_id`, `org_type_criterion_id`, `deadline_criterion_id`, `deadline_utc`, and observation bounds. Only exact enum membership and UTC comparison are allowed. Contradictory caller facts create separate conditional cases; UI/readback may never label them independently verified. Recheck ambiguous/contradictory source prose, missing IDs, before/on/after deadline, timezone variants, stale/unavailable source and disagreement. Version-recorded schema/equivalence/web/serialization probe is the first build-handoff gate.
